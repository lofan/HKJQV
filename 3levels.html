由 Prompt 拉去 System Engineering 的架構圖解

Layer 1: Base

Prompt Engineering (提示詞工程)

核心本質：點樣叫個 Model 做嘢？

  • 撰寫指令 (Instructions)：例如點樣寫「點樣洗張床」？點樣定指令（讓費城點樣燉牛）？
  • 設定結構：Phasing（句式/階段）、Output format（輸出格式）。
Layer 2: Data & Memory

Context Engineering (上下文工程)

核心本質：不只係你問什麼，而係個 Model 見到啲什麼？

  • Model 視覺範圍包括：記憶 (Memory)、工具的 Response、Retrieved doc (檢索文件)、Conversation history (對話歷史)。
  • 黃金平衡：
    • 太多會造成 混亂
    • 太少佢會 答唔到問題
Layer 3: Top System Level

Harness Engineering (治理/外殼工程)

核心本質：不只係你問什麼或你知啲乜嘢，而係講成個 System 點樣包住個 Model 去運作（由 Prompt → Context → Harness）。

💡 這需要思考整個 Architecture (架構)，而唔係單純加啲技術技巧上去。

  • 工具與流水線：用咩工具、工具點樣接入去、Output 去邊、邊啲地方要 Check？
  • 控制與安全：邊啲行為要 Approval (審批)？出錯之後點樣 Retry (重試)？
  • 運維與運作：State (狀態) 點保存、Logs 點記、點做 Evaluation (評估)？
  • 協作機制：人點介入 (Human-in-the-loop)、多個 Agents 點樣運作？

兩大發展方向與哲學

從系統工程出發，業界正走向兩個著重不同哲學的方向：

🪐 OpenClaw

哲學：更廣 (Broader Scope)

  • Agents 可以連接更多不同的工具。
  • 支援更複雜的 Flow (工作流) 與 Skills (技能)。
  • 旨在讓 AI 能夠「做更多嘢」。

🌱 Hermes

哲學：與你一同成長 (Grow with you)

  • 著重隨用戶或業務發展而具備擴展性與適應力。
  • 強調系統的生命週期與持續進化。
